Agentic workflows on Precast + AgentBase

Agents are built on Precast (Mastra) and exposed over A2A. Every call they make — to each other, to SaaS tools, to MCP servers — is brokered by AgentBase: authenticated, credential-injected, audited, and revocable from one place.

The two halves

Precast builds the agents. AgentBase governs them.

A clean split of responsibility: the runtime that produces capable agents, and the control plane that makes them safe to expose and reuse.

Precast · Agent Runtime

Mastra agents, A2A-native

  • ▸Agents + tools + workflows defined in TypeScript, strict-typed with zod at the edges.
  • ▸A2A out of the box — every agent publishes an Agent Card and a JSON-RPC endpoint.
  • ▸Skills = tools — each capability surfaces as an addressable, versioned skill.
  • ▸Scheduling + memory for periodic jobs and stateful threads.

AgentBase · Control Plane

Registry + A2A / MCP proxy

  • ▸Registry of every agent and MCP server, with discovery embeddings.
  • ▸M2M OAuth — callers authenticate with Keycloak client-credentials JWTs.
  • ▸Credential injection — SaaS secrets live here, never in the caller.
  • ▸Zero-trust + audit — inbound auth stripped upstream; every call logged.

One pattern, four workflows

Governed invocation

Whoever calls — a web backend, a scheduler, or another agent — goes through AgentBase to reach a Precast agent or an MCP tool server. The same five guarantees apply every time.

Workflow 01

Sunset Boulevard — booking confirmation

A renter books a motorcycle; the site confirms by SMS — without ever holding an SMS credential.

Flow

  1. Renter books + submits contact form
  2. Backend calls AgentBase to invoke the skill
  3. AgentBase authenticates, injects the m360 credential, forwards
  4. Agent renders the message and sends via m360

Workflow 02

New-hire onboarding orchestration

A new hire lands in Workday. One Precast agent provisions their whole first day across Google Workspace and Slack — through governed MCP calls.

Flow

  1. Workday emits a new-hire event
  2. Onboarding Agent builds the day-one plan
  3. Reads full profile back from Workday (MCP)
  4. Provisions Google Workspace account, Drive, calendar (MCP)
  5. Posts welcome + DMs the checklist in Slack (MCP)

Workflow 03

AEO research + periodic email report

Weekly, OpenClaw scouts how the brand shows up across answer engines; Precast agents score the shift and email a digest to stakeholders.

Flow

  1. Weekly cron starts the sweep
  2. OpenClaw queries research tools via AgentBase (M2M)
  3. Probes each answer engine for brand mentions + citations
  4. AEO Analyst scores visibility and diffs vs. last run
  5. Report Sender emails the digest to stakeholders

Workflow 04

Feature-request triage in Slack

Requests arrive as messages. An agent dedupes, scores, and ranks them — then posts the prioritized list back to Slack.

Flow

  1. Requests posted in #feature-requests
  2. Slack event reaches the agent via AgentBase
  3. Triage Agent dedupes, clusters, RICE-scores, prioritizes
  4. Ranked P0/P1/P2 list posted to #product-triage

The through-line

Same runtime, same hub, four outcomes

Every workflow is a Precast agent doing the thinking and AgentBase doing the governing. Add a workflow by registering an agent and approving a skill — not by rebuilding the plumbing.
